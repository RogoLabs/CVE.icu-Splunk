# TA-cveicu v1.1.0 Design Spec

**Date:** 2026-04-14
**Target Release:** 2026-04-21 (Monday)

## Problem Statement

The modular input fails to register on some Splunk installations, causing the "cve.icu" data input to silently disappear from the UI. Versions 1.0.5 and 1.0.6 attempted fixes, but both were insufficient because:

1. **1.0.5**: Placed the fallback in `__main__`, which was never reached because module-level imports crash first
2. **1.0.6**: Moved the fallback before heavy imports, but it only triggers when `splunklib` fails to import. Since `splunklib` is pure Python, it often imports fine — then the script falls through to `cveicu_lib` imports that pull in `requests → urllib3 → ssl`, which crash on systems with missing SSL shared libraries

The root issue: `splunklib.modularinput.script` itself imports `splunklib.client → splunklib.binding → import ssl`, so even splunklib can fail on broken SSL environments. Our fallback logic tried to be smart about when to use it, and was wrong twice.

Additionally, the existing dashboards use legacy SimpleXML, which is limited and deprecated in Splunk 10.

## Goals

1. Make `--scheme` introspection impossible to break (short of a broken Python interpreter)
2. Provide diagnostic logging when imports fail at runtime so admins can troubleshoot
3. Build a testing framework that catches these issues before release
4. Rework dashboards using Dashboard Studio (Splunk 10+) for a significantly better user experience

## Non-Goals

- No changes to the data ingestion pipeline (stream_events, github_client, cve_processor)
- No changes to the enrichment pipeline (EPSS/KEV)
- No new extracted fields or sourcetypes
- No multi-value field extraction rework (affected_vendor/product stay single-value)

## Design

### 1. Bulletproof --scheme Handler

Move `--scheme` handling to the absolute top of `cveicu.py`, before ALL imports except `sys` and `os`:

```python
#!/usr/bin/env python3
import os
import sys

if "--scheme" in sys.argv:
    sys.stdout.write('<scheme>...hardcoded XML...</scheme>')
    sys.exit(0)

# Everything below can fail safely — the input is already registered
sys.path.insert(0, os.path.join(os.path.dirname(__file__), "lib"))
sys.path.insert(0, os.path.dirname(__file__))

try:
    from splunklib.modularinput import Script, Scheme, Argument, Event, EventWriter
except ImportError:
    Script = object
    ...
```

**Key properties:**

- No `try/except` needed — `sys` and `os` are part of the Python interpreter and cannot fail
- No conditional logic — `--scheme` always emits XML and exits, unconditionally
- The `get_scheme()` method in the class remains for documentation/reference but is never reached during `--scheme` introspection
- The hardcoded XML must stay in sync with `get_scheme()` — enforced by a CI test

**Diagnostic logging for runtime failures:**

When the script runs without `--scheme` (i.e., actual data collection), wrap the import block:

```python
try:
    from splunklib.modularinput import Script, Scheme, Argument, Event, EventWriter
    from cveicu_lib.logging_config import setup_logging, get_logger
    from cveicu_lib.credential_manager import CredentialManager
    from cveicu_lib.github_client import GitHubClient
    from cveicu_lib.checkpoint_manager import CheckpointManager
    from cveicu_lib.cve_processor import CVEProcessor
    from cveicu_lib.resource_manager import ResourceManager, TimeoutManager
except Exception as e:
    sys.stderr.write(
        f"TA-cveicu: Failed to import required libraries: {e}\n"
        f"Python: {sys.executable} {sys.version}\n"
        f"sys.path: {sys.path}\n"
    )
    sys.exit(1)
```

This writes to stderr, which Splunk captures in `splunkd.log`, giving admins a clear diagnostic instead of a naked "exit code 1".

### 2. Testing Framework

Three layers:

#### Layer 1: Unit Tests (no Splunk required)

- **Scheme XML sync test**: Parse both the hardcoded XML string and the output of `get_scheme().to_xml()`, normalize whitespace, compare element trees. Fails if someone updates one but not the other.
- **Import failure simulation**: Temporarily break `sys.modules` entries for ssl/requests/splunklib, invoke the script with `--scheme` via subprocess, assert exit code 0 and valid XML output.
- **props.conf field extraction test**: Feed sample CVE V5 JSON fixtures through the spath expressions defined in props.conf, verify all expected fields extract correctly.
- **Existing tests retained**: checkpoint_manager, cve_processor, resource_manager, zip_cleanup, epss_kev_command.

#### Layer 2: Docker Integration Tests

- Use `splunk/splunk:latest` Docker image (Splunk 10)
- Install from built `.tar.gz` package (not volume mount) to test the real install path
- Tests:
  - Modular input registers: `GET /services/data/modular-input/cveicu` returns 200
  - Data input creation: `POST /services/data/inputs/cveicu/test_input` succeeds
  - Field extractions: ingest sample CVE JSON, query for extracted fields, verify non-null
  - Dashboard loading: `GET /services/data/ui/views/<dashboard_name>` returns 200 for each dashboard
  - Enrichment lookups: verify lookup definition exists
  - Broken environment simulation: run `--scheme` with a Python that has SSL stripped, confirm exit 0

#### Layer 3: GitHub Actions CI Pipeline

Triggers: push to `main`, pull requests.

Three jobs:

1. **Unit tests** — Python 3.9+ matrix, `pytest tests/unit/`, fast (seconds)
2. **AppInspect** — Build `.tar.gz`, run `splunk-appinspect inspect --mode precert`, fail on any error/failure
3. **Docker integration** — Start Splunk container, install package, run `pytest tests/integration/`, tear down

PR gate: all three jobs must pass.

### 3. Dashboard Rework (Dashboard Studio, Splunk 10+)

All dashboards use Dashboard Studio JSON format. All legacy SimpleXML dashboards in `default/data/ui/views/` are removed.

#### Dashboard 1: CVE Explorer (Analyst)

Daily workhorse for searching and filtering CVEs.

- **Filter bar**: time range, vendor, product, severity, state (published/rejected), CWE category
- **Results table**: CVE ID, title, vendor, product, CVSS score, severity, date published. Sortable columns.
- **Drill-down**: Click any row to see full detail — description, all CVSS versions, ADP data
- **Ingest sparkline**: volume over time to spot large dumps

**Backing searches**: Live searches against the index with lookup enrichment joined at search time.

#### Dashboard 2: Risk Priority (Analyst)

What actually matters. Leads with EPSS + KEV + CVSS enrichment.

- **Top KPIs**: CVEs in CISA KEV, high-EPSS CVEs from last 7 days
- **Risk-ranked table**: CVE ID, CVSS score, EPSS probability, KEV status, SSVC decision, computed risk score
- **Filters**: EPSS threshold, KEV-only toggle, minimum severity
- **Trend chart**: new high-risk CVEs per day/week

**Backing searches**: Live searches joined with `epss_lookup.csv`, `kev_lookup.csv`, `risk_priority_lookup.csv`.

#### Dashboard 3: Vulnerability Landscape (Executive)

High-level posture for leadership and weekly briefings.

- **KPI row**: total CVEs, new this week, critical/high count, % with EPSS > 0.5
- **Severity distribution**: donut or bar chart
- **Top 10 vendors**: by CVE count
- **Trend lines**: CVEs published per week/month
- **KEV growth trend**

**Backing searches**: Scheduled saved searches → lookup CSVs for fast loading.

#### Dashboard 4: Operational Health (Admin)

Is the add-on working?

- **Input status**: last successful run, events ingested, error count
- **Checkpoint state**: current baseline tag, last delta processed
- **Enrichment freshness**: EPSS/KEV/risk lookup last update timestamps
- **Data volume**: events per day, index size estimate

**Backing searches**: Mix of `index=_internal` queries and lookup metadata.

### 4. Breaking Changes

- **Minimum Splunk version**: Raised from 8.2 to 10.0
- **Legacy dashboards removed**: Users on Splunk 8.x/9.x lose dashboards on upgrade. Data ingestion continues to work — only the views are affected.
- **Updated in**: app.conf (Splunk version requirement), README (requirements section), Splunkbase listing
